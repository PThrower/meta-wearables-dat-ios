# PRD-007: Google OAuth Authentication

**Status:** In Progress
**Branch:** `feat/google-oauth-auth`
**Depends on:** PRD-006 (Enterprise Platform)
**Date:** 2026-04-10

---

## Problem

The relay platform is fully open -- any client can publish, view, or access stats without identity. With multi-session routing live and enterprise deployment approaching, auth is the next blocker.

## Solution

Google OAuth via ID token verification on all protected routes.

### Architecture

```
Browser (GIS popup)              iOS (ASWebAuthenticationSession)
      |                                    |
      v Google                             v Google
  ID Token (JWT)                      ID Token (JWT)
      |                                    |
      v ws://.../view?token=JWT           v ws://.../publish?session=X&token=JWT
  +-----------------------------------------------------------+
  |                    Bun Relay Server                        |
  |  auth.ts: verifyToken() on every WS upgrade + /stats      |
  |  Attach userId/email to WsData                            |
  |  Session ownership: ownerId on Session                    |
  |  RELAY_NO_AUTH=1 bypasses all checks (dev mode)           |
  +-----------------------------------------------------------+
```

## Route Auth Matrix

| Route | Auth Required | Notes |
|-------|---------------|-------|
| `GET /` | No | Public directory page |
| `GET /sessions` | No | Public session list |
| `GET /session/<id>` | No | Serves viewer HTML |
| `GET /relay-player.js` | No | Static JS |
| `GET /gallery/api` | No | Public gallery |
| `GET /stats` | Yes | Any authenticated user |
| `WS /publish?session=&token=` | Yes | Owner only (session ownerId match) |
| `WS /view?session=&token=` | Yes | Any authenticated user (if session isPublic) |
| `WS /tap/audio?session=&token=` | Yes | Any authenticated user |

## Implementation

### Server (`relay/server/src/`)

- **`auth.ts`** (new): `verifyToken()` and `extractToken()` using `google-auth-library`
- **`types.ts`**: Added `userId`, `email` to `WsData`; `ownerId`, `ownerEmail`, `isPublic` to `Session`
- **`session-registry.ts`**: Session ownership in `claimPublisher()` (403 on owner mismatch), access control in `addViewer()`
- **`server.ts`**: Auth middleware on `/stats`, WebSocket upgrades (publish, view, audio-tap)
- **`package.json`**: Added `google-auth-library` dependency

### Viewer (`relay/viewer/`)

- **`index.html`**: GIS popup login overlay, token stored in localStorage, passed as query param
- **`relay-player.js`**: 401/403 close code handling, stops reconnect on auth failure

### iOS Client

- **`RelayStage.swift`**: `connect(to:idToken:)` appends `&token=` to URL
- **`StreamSessionViewModel.swift`**: Acquires token before relay connection
- **`Info.plist`**: Google client ID and OAuth redirect scheme

## Token Sources (extraction order)

1. Query param: `?token=<jwt>`
2. Authorization header: `Bearer <jwt>`
3. Cookie: `relay_token=<jwt>`

## Dev Mode Bypass

`RELAY_NO_AUTH=1` in environment:
- `verifyToken()` returns `{ sub: "dev", email: "dev@localhost" }`
- All routes accessible without token

## Doppler Secrets

| Key | Purpose |
|-----|---------|
| `GOOGLE_CLIENT_ID` | Web OAuth client ID from GCP |
| `GOOGLE_IOS_CLIENT_ID` | iOS OAuth client ID |
| `GOOGLE_IOS_CLIENT_SECRET` | iOS OAuth client secret |
| `RELAY_NO_AUTH` | Set to `"1"` for local dev bypass |

## Verification

1. `curl https://relay.simulationapi.com/stats` returns 401
2. With valid Bearer token, returns 200
3. WebSocket to `/publish?session=test` without token closes 401
4. Publisher A creates session; Publisher B rejected with 403
5. Browser viewer shows Google login, then stream plays
6. `RELAY_NO_AUTH=1` bypasses all checks
